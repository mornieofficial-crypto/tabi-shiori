# Security Baseline
Version: 1.0

## 1. 基本方針
- 動くことと安全であることは別と考える
- 不要な個人情報・権限・外部通信は追加しない
- セキュリティに関わる重要変更は独断で実装しない
- 公開前に必ずセキュリティ監査を行う

## 2. 秘密情報
- APIキー、秘密鍵、トークン、パスワードをソースコードへ直接書かない
- 秘密情報をGitへコミットしない
- クライアントアプリから見える場所に秘密情報を置かない
- .env を使用する場合も、公開される環境変数と秘密情報を区別する
- .env.example には実際の秘密情報を書かない

## 3. 個人情報・ユーザーデータ
- 必要のない個人情報は収集しない
- 収集するデータ、保存場所、利用目的を明確にする
- ログに個人情報や秘密情報を出力しない
- 外部サービスへ送信するデータを把握する

## 4. 認証・認可
- 認証・認可を独自実装しないことを原則とする
- ログイン済みであることだけでアクセス権限があると判断しない
- ユーザーごとのデータアクセス範囲を確認する
- 管理者権限などの強い権限をクライアント側だけで判定しない

## 5. 入力値
- ユーザー入力、URL、ファイル、APIレスポンスなど外部入力を信用しない
- 型、長さ、形式、許容値を検証する
- 想定外の入力でもクラッシュしないようにする

## 6. API・通信
- 原則HTTPSを使用する
- APIの認証・認可方式を確認する
- エラーメッセージに内部情報を出しすぎない
- 不要なAPIエンドポイントを公開しない

## 7. DB・保存
- DBのアクセス権限を最小限にする
- 他ユーザーのデータへアクセスできないことを確認する
- 機密データを平文保存しない
- 保存が不要なデータは保存しない

## 8. 外部ライブラリ・SDK
- dependency追加は必要性を確認してから行う
- 不要なdependencyは追加しない
- 既知の脆弱性がないか確認する
- 外部SDKが収集・送信するデータを確認する

## 9. ログ・デバッグ
- 本番環境で不要なデバッグ情報を出さない
- APIキー、トークン、個人情報をログへ出力しない
- 開発専用機能を本番へ残さない

## 10. AI開発ルール
- AIが生成したコードを安全だと前提にしない
- セキュリティに影響する変更は明示する
- 認証、DB、API、課金、保存方式、権限、外部SDKの変更時はSecurity Impactを確認する
- 判断できないセキュリティ問題は勝手に回避せず報告する

## 11. 公開前
公開前に以下を別工程で監査する。

- 秘密情報
- 個人情報
- 認証・認可
- API
- DB
- 入力値
- 外部SDK
- dependency
- ログ・デバッグ
- 権限
- プライバシー設定
- App Store / Google Playの申告内容との整合性

## 12. 高リスク判定
以下を扱う場合は通常より厳しい監査を行う。

- 医療・健康情報
- 金融情報
- 本人確認情報
- 正確な位置情報
- 子どもの個人情報
- パスワードや認証情報
- ユーザー間通信
- ファイルアップロード
- クラウドDB
- 独自バックエンド
- 企業や顧客の機密情報

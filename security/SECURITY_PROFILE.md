# Security Profile
Version: 1.0 / 最終更新: 2026-10-17(Phase 1 完了時点)

## 1. 基本情報
- アプリ名：旅のプラン(旅のしおり)
- プラットフォーム：Web(PWA)。iPhone Safari 優先
- 開発環境：素の HTML / CSS / ES Modules(ビルドなし、依存パッケージなし)
- 公開予定：未定(公開・push・deploy は事前にユーザー確認)

## 2. 扱うデータ
- ユーザーが入力するデータ：旅行名、行き先、日程、メンバー名・絵文字・誕生日(月日)、候補の場所(名前・住所・メモ・緯度経度)、予定、持ち物、メモ
- 端末内に保存するデータ：上記すべて(IndexedDB)、アプリの色(IndexedDB)
- クラウドに保存するデータ：**同期を使う旅行だけ**、端末で暗号化した旅行データ(誕生日・写真を除く)を中継サーバーに置く。同期を設定しなければ、なし
- 個人情報：メンバー名、誕生日(月日のみ)、旅行の予定
- 機密情報：なし
- 子どもの情報：入力されうる(家族旅行)が、アプリ側では区別・収集しない
- 健康・医療情報：なし
- 金融情報：なし
- 正確な位置情報：端末の位置情報は**取得しない**。ユーザーが手入力した場所の緯度経度のみ

## 3. 保存場所
- 端末内保存：IndexedDB(`tabi-shiori`)。旧試作版の localStorage からは初回のみ取り込み(元データは削除しない)
- 使用DB：IndexedDB のみ
- クラウドDB：中継サーバー(Cloudflare Workers + Durable Objects)に暗号文・版番号・書き込み合言葉のハッシュだけ(同期を使うときのみ)
- バックアップ：ユーザーが JSON を書き出す方式(バックアップ用=誕生日あり / 共有用=誕生日なし)
- 暗号化の有無：端末内の保存と書き出し JSON は平文。**同期で送る内容は AES-GCM 256 で端末側で暗号化**(鍵は共有リンクの # 以降のみ。サーバーには送られない)

## 4. アカウント・認証
- ログイン機能：なし(同期は、リンクに入った鍵を知っていることが資格。アカウントなし)
- 認証方式：なし
- ユーザーごとのデータ分離：端末(ブラウザのオリジン)単位
- 管理者権限：なし
- パスワードを自前で扱うか：いいえ

## 5. 外部通信・API
- 外部API：**同期サーバーを設定し、旅行を同期するまでは、一切通信しない**。同期時のみ、設定したサーバー(https://*.workers.dev)へ通信する。CSP の connect-src は 'self' と https://*.workers.dev だけ
- 独自API：なし
- 通信するデータ：同期時のみ。暗号文、部屋の名前(鍵から作った推測できない乱数)、書き込み用合言葉(鍵から作る)。旅行名・場所・誕生日・写真などは平文では送らない
- APIキー：なし
- 秘密情報：なし
- HTTPS使用：公開時は必須(Service Worker と PWA に必要)
- ユーザー操作で開く外部リンク：Yahoo!マップ検索、Appleマップ、`yjcarnavi://`。場所名・住所・緯度経度が URL に含まれる(ユーザーがボタンを押したときだけ)

## 6. 外部サービス・SDK
- 分析SDK：なし / 課金：なし / 広告：なし / クラッシュ解析：なし / 通知：なし / 認証サービス：なし / AI API：なし
- 外部ライブラリ・CDN・Webフォント：なし

## 7. 課金
- 課金機能：なし

## 8. 端末権限
- ファイル選択(写真の選択)のみ。使用しない権限:カメラ・マイク・位置情報・通知・連絡先 すべて不使用)

## 9. ユーザー入力
- 自由入力：あり(全項目に長さ上限。表示時は必ず HTML エスケープ)
- URL入力：なし
- ファイルアップロード：なし(サーバーがない)。ユーザーが選んだ**写真**(背景・場所のサムネ)は端末内で縮小し JPEG に再エンコードして(撮影場所などのメタデータを除去)、旅行データの一部として IndexedDB に保存する。外部へは送らない
- 外部からのインポート：JSON(30MB 上限・写真入りバックアップを想定。写真は `data:image/jpeg;base64` かつサイズ上限内のものだけ通す。型・長さ・範囲・ID を検証し、未知の項目は捨てる。旅行IDは振り直して既存を上書きしない)
- QRコード等：なし

## 10. 開発・秘密情報管理
- .env使用：なし
- Git管理：未初期化(2026-10-17 時点)
- GitHub公開範囲：未定
- 私的データ：`private/`(個人の旅行の実データ)は `.gitignore` 済みで、配信サーバー(`tools/serve.mjs`)も `app/` だけを配信。ユニットテストで `app/` に JSON が無いことを確認
- 秘密情報をコードへ直接記載していない：確認済み(秘密情報自体がない)
- .envがGit除外されている：確認済み(.gitignore に記載)

## 11. 想定リスク
- 端末の紛失・盗難・共有端末(データは平文で端末内にある)
- iPhone Safari の保存領域が、長期間未使用で消される可能性(→ persist 要求とバックアップ導線)
- 書き出した JSON の取り扱い(LINE などで送ると第三者に渡りうる。共有用では誕生日を除外)
- Service Worker が古いファイルを返す(→ network-first、キャッシュは固定ファイルのみ)
- 将来の同期機能(暗号化リアルタイム同期)で、鍵付きリンクの転送・漏えい

## 12. リスクレベル
- **MEDIUM**(Phase 2:同期の追加により、LOW から再判定)。同期を設定しない限り、通信しないので実質 Phase 1 と同じ

### Phase 2(同期)で増えたリスクと対策
- リンクの転送・漏えい:リンクを知る人は読み書きできる → 受け渡し先を2人に限る、相手以外に渡さない、同期をやめる/鍵を作り直す(新しいリンクで始め直す)
- サーバーに見えるもの:更新の時刻・内容の大きさ・接続元(暗号化では隠せない)
- 部屋の乱立(第三者が勝手に部屋を作る):アカウントがないため完全には防げない。Cloudflare 側の無料枠の上限が事実上の歯止め(未実装:期限切れでの自動削除)
- 取り込む内容の検証:相手から来た内容も、必ず normalizeTrip を通す(未知の項目は捨て、長さ・範囲・IDを検証)
- 中継サーバー(relay/worker.js)は、実際の Cloudflare 上では未確認

### 判定理由
- ログインなし、独自バックエンドなし、クラウドDBなし、外部通信なし、端末権限なし
- ただし誕生日と旅行予定という個人情報を端末内に持つ。**Phase 2(同期)に入る時点で必ず MEDIUM 以上で再判定する**

# Security Workflow
Version: 1.0

## 新規アプリ開始時
1. アプリ内に `security/` フォルダを作成し、以下をコピーする

   - SECURITY_BASELINE.md
   - SECURITY_PROFILE.md
   - CLAUDE_SECURITY_RULES.md
   - RELEASE_SECURITY_CHECKLIST.md
   - SECURITY_RISK_LEVELS.md
   - SECURITY_WORKFLOW.md
   - SECURITY_TRIGGER_GUIDE.md

2. SECURITY_PROFILE.md の基本情報を埋める

3. SECURITY_RISK_LEVELS.md を参考に、
   LOW / MEDIUM / HIGH で暫定リスクを判定する

---

## 通常開発時
Claude Codeには作業前に以下を確認させる。

- CLAUDE_SECURITY_RULES.md
- SECURITY_PROFILE.md

セキュリティに影響する変更があれば、
完了報告に Security Impact を記載させる。

---

## 以下を追加・変更したとき
SECURITY_PROFILE.md を更新する。

- 認証
- API
- DB
- 課金
- 広告
- 分析SDK
- 外部SDK
- 個人情報
- 位置情報
- 通知
- ファイル・画像アップロード
- 端末権限
- 保存方式
- 外部通信

必要ならリスクレベルも再判定する。

---

## 公開前
1. SECURITY_PROFILE.md を最新化する
2. SECURITY_RISK_LEVELS.md でリスクを再判定する
3. RELEASE_SECURITY_CHECKLIST.md を使って監査する
4. 問題があれば修正する
5. 再監査する

最終判定：

- PASS → 公開可能
- HOLD → 修正後に再監査
- STOP → 公開しない

---

## 公開後
以下の変更時は再度セキュリティ確認を行う。

- 認証
- DB
- API
- 課金
- 個人情報
- 外部SDK
- 権限
- 保存方式
- その他セキュリティ影響が大きい変更

HIGHリスクの場合は、
必要に応じて人間のセキュリティ専門家による確認も行う。

## セキュリティ問題が見つかったとき

### P0：重大
例：
- 秘密情報の漏洩
- 他ユーザーのデータを閲覧できる
- 認証を回避できる
- 個人情報が意図せず外部送信される

対応：
- 作業・公開を停止する
- 先に原因を特定する
- 修正後に必ず再監査する
- PASSになるまで公開しない

### P1：重要
例：
- 不要な権限
- 不十分な入力検証
- SDKのデータ収集が未確認
- 本番にデバッグ設定が残っている

対応：
- 公開前に修正する
- 修正後に該当項目を再確認する

### P2：改善
例：
- ドキュメント不足
- 将来リスクになる設定
- すぐに悪用される可能性は低い改善事項

対応：
- 公開可否への影響を確認する
- 必要なら公開前に修正
- 後回しにする場合は記録を残す

## 修正時のルール

1. ChatGPTが問題と修正方針を整理する
2. Claude Codeへ修正指示を渡す
3. Claude Codeが実装・テストする
4. Claude CodeがSecurity Impactを報告する
5. ChatGPTが再監査する
6. 問題が解消したら次へ進む

## テンプレート更新ルール

### 共通テンプレート
全アプリ共通のセキュリティテンプレートを1か所で管理する。

各アプリへコピーするときは、常にこの共通テンプレートの最新版を使用する。

各テンプレートにはVersionを記載する。

### バージョン更新
- 文言修正・項目追加など軽微な変更：1.0 → 1.1
- 運用方法や構成が大きく変わる変更：1.x → 2.0

### 既存アプリへの反映
共通テンプレートを更新しても、
既存アプリ内のsecurityファイルを自動で上書きしない。

以下のタイミングで最新版との差分を確認する。

- 公開前監査
- 大きな機能追加時
- セキュリティ基準を大きく変更したとき
- 重大な脆弱性や新しいリスクを把握したとき

### アプリ固有ファイル
SECURITY_PROFILE.md は各アプリ固有のため、
共通テンプレート更新で上書きしない。

### 更新禁止
既存アプリへ最新版を反映するとき、
SECURITY_PROFILE.md や監査記録を消さない。

### 原則
最新版だからという理由だけで、
既存アプリのファイルを一括上書きしない。
差分を確認して必要な変更だけ反映する。
